# Webhook 개발 현황

Webhook 구독 API와 작업자는 로컬에서 개발·검증 중이며 운영 서비스에서 실행되지 않습니다. 기본적으로 API는 비활성 상태입니다. 공개 운영에 필요한 저장 공간 제한과 악용 방지 검증이 남아 있으므로 아직 활성화하지 마세요.

구독 관리 토큰은 생성할 때 한 번만 반환하고 DB에는 SHA-256 해시를 저장합니다. 대상 URL과 서명 키는 발송에 필요하므로 DB에 보관합니다. 새 DB는 가능한 운영체제에서 소유자만 읽고 쓸 수 있는 권한으로 생성하지만, 기존 파일과 상위 디렉터리의 권한은 운영자가 별도로 확인해야 합니다. 백업과 SQLite 보조 파일에도 동일한 보호가 필요합니다.

전송 대상은 현재 Discord와 Google Chat의 정해진 HTTPS 경로만 허용합니다. 리다이렉트와 환경 프록시는 사용하지 않고, 동일 구독과 이벤트 ID는 한 번만 큐에 넣습니다. 작업자 임대 만료 시 다시 시도하므로 **전송 성공 직후 프로세스가 종료되면 중복 전송될 수 있습니다**. 재시도에는 같은 이벤트 ID를 사용하지만 외부 서비스가 중복을 제거한다는 보장은 없습니다.

로컬 구현에서는 같은 SQLite 파일에 Webhook 저장소가 초기화된 경우, 이력 관측과 해당 학급의 전송 큐 삽입이 한 트랜잭션에서 이루어집니다. 최초 관측은 알림을 만들지 않습니다. 별도 파일에 저장소를 만들면 이력과 연결되지 않습니다.

합성 데이터로만 실험할 때는 기존 이력 DB 경로를 `OPENCIGAN_HISTORY_DB`에 설정하고 `OPENCIGAN_WEBHOOKS_ENABLED=1`을 지정합니다. `POST /api/v1/webhooks`의 JSON 필드는 `school`, `grade`, `class`, `destination`입니다. 응답의 `id`와 일회성 `token`을 보관하고, 조회·삭제 시 `/api/v1/webhooks/{id}`에 `Authorization: Bearer <token>`을 보냅니다. 토큰은 URL이나 로그에 넣지 않습니다. 삭제는 이미 전송 중인 요청을 취소하지 못합니다.

작업자는 같은 환경 변수를 설정한 별도 프로세스에서 `python -m backend.webhook_worker`로 실행합니다. 시스템 서비스는 아직 제공하거나 활성화하지 않습니다. 최초 관측은 기준만 만들며, 이력과 Webhook DB가 같은 파일이어야 합니다. 자동 조회 기능이 없으므로 누군가 시간표를 조회하고 새 원본 데이터가 수집될 때만 변경을 관측합니다.

구독별 대기·발송 중 항목은 최대 1,000건입니다. 꽉 차면 새 알림은 생략하고 구독 조회의 `dropped_events`가 증가하지만 시간표 이력은 유지됩니다. 전송 시도는 최대 6회이며, 완료·실패 항목은 30일 후 작업자 점검 시 정리됩니다. SQLite 파일의 할당 공간은 삭제 직후 자동으로 줄어들지 않을 수 있습니다.

실제 사용 전에는 구독 API 악용 방지, 큐 저장 공간 상한, 작업자 운영, 보관·삭제 및 비밀값 보호를 완성하고 검증해야 합니다.
