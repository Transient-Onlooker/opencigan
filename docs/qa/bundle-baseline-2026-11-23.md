# 프런트 번들 기준선 — 2026-11-23

## 제안 기능 지연 로딩 실험 — 2026-11-26

동일 프런트 소스와 `VITE_BUILD_SHA=0123456789abcdef0123456789abcdef01234567`, Windows·Node·Vite 환경에서 설정의 제안 컴포넌트만 분리했다. 루프백 미리보기와 빈 Chromium 컨텍스트에서 외부/API 요청을 차단한 단일 표본이며 운영 전송량이나 체감 시간을 보장하지 않는다. 같은 조건의 `node scripts/measure-initial-assets.mjs` 결과는 390/1366px 모두 JS 76,157→74,977바이트, CSS 22,877→22,685바이트, 폰트 333,884바이트였다(응답 본문 인코딩 크기). `node scripts/measure-install-assets.mjs`는 서비스 워커 설치 요청까지 함께 센다: 390px에서 JS 152,482→150,122바이트, CSS 45,820→45,436바이트, 폰트 333,884바이트였다. 페이지와 서비스 워커가 같은 자산을 각각 요청한 바이트도 포함하므로 초기 화면 수치와 합산하지 않는다.

위 브라우저 수치는 경합 수정 전 실험이다. 경합 수정 후 같은 버전 설정의 빌드 산출물에서 서비스 워커 자산의 파일별 gzip 합계는 JS 75,131→74,050바이트, CSS 22,641→22,437바이트였다. 파일별 gzip 크기는 실제 운영 전송량과 다르다.

설정 진입 시 청크와 기존 제안 API를 불러오며, 오프라인 첫 진입에서는 제안이 나타나지 않지만 다른 설정은 사용할 수 있다. 청크를 불러오지 못하면 새로고침 후 다시 시도하는 버튼을 제공한다. 최초 기능 진입에는 별도 청크 요청이 추가되며, 서비스 워커는 이 청크를 사전 캐시하지 않는다. 실제 모바일 기기와 운영 전송량은 검증하지 않았다.

로컬 `npm run build` 산출물을 측정했다. 소스는 `b0dc178d2f62b3965b7ca8817e5883995d20af58`이며 측정 당시 최신 `main` `2932958000bfc4cfc7e4f9e39a260874581bda37`과 `frontend` 파일 차이는 없다. Windows x64, Node 26.13.0, Vite 6.4.6 환경이다. gzip 크기는 Python `gzip.compress`로 계산한 파일별 크기이며 전송 서버의 압축 방식과 다를 수 있다.

| 자산 | 원본 바이트 | gzip 바이트 |
| --- | ---: | ---: |
| 메인 JS | 206,430 | 70,129 |
| HTML에 명시된 JS preload 3개 합계 | 4,290 | 2,242 |
| 메인 CSS | 91,081 | 22,566 |
| 별도 대형 JS 청크 | 440,122 | 181,570 |

빌드 전체 `assets`는 JS 11개 687,110바이트, CSS 4개 198,362바이트, WOFF2 92개 2,957,724바이트다. 전체 파일 크기는 최초 방문 시 모두 다운로드한다는 뜻이 아니다. 폰트 서브셋은 사용 문자와 브라우저 동작에 따라 요청량이 달라진다.

PDF 내보내기 코드는 `pdf-lib`를 동적으로 가져오며, 대형 JS 청크는 생성된 `index.html`의 초기 스크립트·preload 목록에 없다. 메인 스크립트의 이미지 생성 코드는 초기 번들에 포함된다. 이를 분리할 경우 오프라인 셸의 캐시 목록과 모바일 공유의 사용자 활성화 조건을 함께 검증해야 한다.

추가로 동일 빌드의 로컬 Vite 미리보기를 사용해 빈 브라우저 컨텍스트에서 첫 방문을 측정했다. 외부·API 요청과 서비스 워커는 차단했다. Chromium에서 390×844와 1366×844 모두 JS 4개 73,387바이트, CSS 1개 22,807바이트, WOFF2 13개 333,884바이트의 encoded body를 요청했다. 폰트는 표시된 문자에 따라 달라지고, 프로토콜·압축·캐시·OS·브라우저에 따라 실제 전송량은 달라진다. HTML 문서는 이 자원 합계에 포함하지 않는다.

재측정은 `frontend`에서 `npm run build` 후 `npx vite preview --host 127.0.0.1 --port 4174 --strictPort`로 미리보기를 열고, 별도 터미널에서 `node scripts/measure-initial-assets.mjs`를 실행한다. 종료 후 미리보기 서버를 중지한다. 이 스크립트는 루프백만 허용하고 다른 출처와 API 요청을 차단한다.

운영 환경의 실제 전송량·로딩 시간 및 최적화 전후 차이는 측정하지 않았다. ST-13은 후속 최적화와 회귀 검증 전까지 미완료다.

## 이미지 내보내기 분리 실험 — 2026-11-25

기준 커밋 `0c972b7`에서 이미지 내보내기를 별도 청크로 분리하는 [실험 PR #230](https://github.com/Transient-Onlooker/opencigan/pull/230)을 검토했다. 같은 로컬 빌드 환경의 메인 JS는 gzip 71.59kB에서 68.89kB로 줄었고, 서비스 워커를 차단한 최초 JS 응답 본문은 74,167바이트에서 71,584바이트로 줄었다.

오프라인 이미지 저장을 유지하기 위해 서비스 워커가 새 청크를 설치 시 미리 받도록 한 뒤 빈 Chromium 프로필로 다시 측정했다. 루프백 프록시에서 API를 차단하고 페이지를 불러온 뒤 서비스 워커 활성화까지 완료했을 때 JS 응답 본문 합계는 **74,801바이트에서 75,426바이트로 625바이트 증가**했다. 이는 해당 로컬 서버·압축·캐시 조건의 단일 측정이며 운영 트래픽 전체를 대표하지 않는다. 모바일 실기기 공유 활성화도 미검증이다. 첫 방문 총 전송량 개선이 확인되지 않아 이 구현은 병합하지 않았으며, ST-13은 다른 근거 있는 최적화와 실측이 남아 있다.
