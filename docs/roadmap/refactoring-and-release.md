- [ ] Python API(`backend/app.py`)와 Workers 실험(`workers-api/worker.py`)의 라우팅·요청 검증·응답 변환 중복을 대조하고, 공통 계약/테스트를 기준으로 유지할 구현을 정리해 양쪽 동작이 어긋나지 않게 관리
- [ ] `phase0/`, `phase0-mvp/`, `workers-api/`의 현재 사용 여부와 재현 필요성을 확인하고, 더 이상 유지하지 않는 실험 코드는 저장소 아카이브로 이동하거나 정리
- [ ] 추적 중인 wheel 등 바이너리 의존성의 실제 빌드 필요성을 확인. 동일 SHA-256의 중복 wheel은 한 곳에서 관리하고, Workers용 `pycryptodomex` wheel은 재현 가능한 빌드·배포에 필요한 경우에만 유지
- [ ] 프런트엔드 프로덕션 빌드의 JS/CSS 청크 크기와 의존성 구성을 측정하고, 중복 포함·불필요한 의존성·초기 로딩에 포함된 선택 기능을 확인해 필요한 기능만 지연 로딩하도록 정리

## 구현 순서와 검증

코드 구조·저장소 정리 항목은 **PDF로 생성되는 결과물의 파일 크기 최적화가 아니라**, 소스 코드의 복잡도·중복·저장소에 추적되는 불필요한 파일·브라우저에 전달되는 JS/CSS 번들 크기를 대상으로 합니다.

아래 작업 묶음은 위 우선순위와 연결됩니다.

1. **배치 1 (P0/P1 UI 정리 및 기본 개인화 — 완료)**: 탭 정리, 수집 시각, 교사 격자, 알레르기 경고, 고해상도 PNG, 과목/교사 표기 설정.
2. **배치 2 (P1 시간표 개인화 고도화 — 로컬 구현 완료, 기기 검증 대기)**: 학교별 교시 시작·종료 시각 입력/검증, 오늘 수업 요약, 종료/타 요일 수업 흐리기, 애니메이션 제어, 급식 가시성 설정.
3. **배치 3 (P1 설정 관리 및 P2 외부 연동 최적화 — 로컬 구현 완료, 게이트 대기)**: 학교별 설정 JSON 백업/복원/초기화, 캘린더 구독 하루 요약 모드 및 ETag/304 조건부 응답 로컬 구현.
4. **배치 4 (P0/P1 모바일 사용성)**: 좁은 화면의 시간표 행 높이와 버튼 배치를 개선했습니다. 실기기 검증은 남아 있습니다.
5. **배치 5 (P1/P2 확장 기능)**: 학급별 설정과 오프라인 시간표 조회, 개인 시간표·일정의 로컬 저장·PNG를 구현했습니다. 모바일 PWA 실기기 검증은 후속 과제입니다.
6. **배치 6 (P0/P2 공개 서비스 전환 — 예정)**: 공개 도메인 배포, 프록시 환경 IP 제한 및 외부 구독 접근성 검증, 공개 API 운영 정책 수립.
7. **배치 7 (P1/P2 코드 구조·저장소 정리 — 진행 중, 전체 완료 아님)**: **현재 작업 마무리 → RPi 배포 → QA 기준선 확보 후 착수**. 프런트엔드 상태·화면 분리, CSS 정리, 백엔드 라우팅 분리, Python/Workers 구현 중복과 과거 실험 파일·바이너리 의존성 점검, 프로덕션 JS/CSS 번들 측정.

### 배치 7 착수 조건과 리팩터링 순서

**구체적인 코드 분석·제안 파일 구조·함수 이동 대상·단계별 Draft PR·테스트/호환성 기준:** [리팩터링 실행 설계](../refactoring-plan.md). 아래는 우선순위 체크리스트이며 실제 구현 순서와 회귀 기준은 연결된 문서에 따른다.

**착수 원칙:** 현재 구현 중인 작업을 안전하게 마무리하고 RPi에 반영한 뒤, 실제 동작 QA를 기준선으로 확보한다. 모든 사소한 버그가 사라질 때까지 기다리지는 않는다. 서비스 사용·데이터 정확성·배포를 막는 결함은 먼저 수정하고, 그 외 재현 가능한 문제는 기록한 뒤 리팩터링 중 회귀와 구분한다. 신규 기능 추가는 배치 7 동안 가급적 보류한다.

**A. 리팩터링 전 기준선 확보**

- [ ] 현재 변경 작업을 마무리하고 최신 커밋의 Python·프런트 단위 테스트, Svelte 검사, Chromium/WebKit E2E, 빌드 및 GitHub Actions 결과 확인
- [ ] 해당 버전을 RPi API·LAN 미리보기의 실제 적용 범위에 맞게 배포하고 커밋 SHA·배포 결과·이전 버전 복귀 지점을 기록. 내부망 배포와 공개 도메인 배포를 혼동하지 않기
- [ ] QA 기준선 기록: 학교·학년·반·주차 전환, 늦은 응답/공유 링크 복원, 복수 수업, 급식, 개인 설정·오프라인 복원, PNG/PDF(다크모드 PDF는 흰 배경), 모바일 내비게이션 및 기존 API·ICS 계약. 실제 iOS/Android·외부 접속은 가능한 범위에서 별도로 확인하고 미검증 항목 표시
- [ ] QA에서 발견한 문제 중 P0·데이터 무결성·배포 차단 결함을 먼저 수정. 나머지는 재현 절차·기대 동작·영향 범위를 남겨 리팩터링 전후 비교 기준으로 사용

**B. 리팩터링 실행 순서 — 각 단계 완료 후 회귀 확인**

- [ ] **1. 상태 흐름 파악·테스트 보강**: `App.svelte`의 학교/학급/주차 상태, 선택·공유 복원, `localStorage` 쓰기, API 요청·취소 경로를 추적해 상태 소유권과 불변 동작을 명확히 하고 부족한 경합 테스트 보강
- [ ] **2. 선택 상태·비동기 요청 경계 분리**: 학교·학년·반·주차 선택을 한 모듈/상태 소유자로 모으고, 응답 유효성 검사·취소·오프라인 복원·저장 순서를 일관화. 이 단계에서 화면 구성은 유지
- [ ] **3. 도메인 로직·저장 책임 분리**: 시간표/급식 데이터 처리, 설정·개인화·즐겨찾기, 공유·내보내기 관련 순수 로직과 브라우저 저장 책임을 분리. 기존 API 요청 수·캐시 동작과 저장 키 호환 유지
- [x] **4. Svelte 화면 컴포넌트 분리**: 선택·시간표·급식·설정·공유 화면을 컴포넌트로 추출하고 상태와 콜백을 명시적으로 연결했다. 저장·공유 복원과 시간표 화면은 단위·브라우저 회귀 검사를 유지한다. [구조와 검증](../refactoring-plan.md#단계별-확인-현황--2026-11-16)
- [x] **5. CSS 정리**: 컴포넌트 전용 스타일과 공통·시간표·반응형 규칙을 분리하고 모바일 규칙을 통합했다. Chromium·WebKit에서 320·375·390·667·768·1280px, 라이트·다크, 입력 포커스와 밀도를 검사했다. 실제 모바일 기기 검증은 별도다.
- [x] **6. 백엔드 라우팅 분리**: 시간표·급식·캘린더·이력·관리자·통계·웹훅 처리와 공통 검증/응답을 분리했다. 기존 진입점과 패치 경로, 상태 코드·헤더·제한·ICS·로그 계약은 API 및 WSGI 회귀 테스트로 유지한다. [구조와 검증](../refactoring-plan.md#단계별-확인-현황--2026-11-16)
- [x] **7. 접속 로그 모듈 정리 검토**: `AccessLogStore`와 `AccessLogRecorder`는 이미 분리된 클래스이며 분석 기록기와 종료 정책이 달라 별도로 유지한다. 보관 기한, 큐 포화·flush·종료는 `tests/test_access_logs.py`와 `tests/test_access_log_api.py`로 검증한다. [조사 근거](../refactoring-plan.md#pr-7--로그운영기록-계층-refactorlogging-boundaries-필요할-때만)
- [x] **8. 실험 코드·의존성 정리**: Workers와 두 실험 경로의 재현 참조를 확인해 보존하고, 중복 wheel을 통합했다. Workers 필수 wheel과 Python/Workers 공통 계약 테스트를 유지한다. [조사 근거와 제한](../refactoring-plan.md#pr-8--과거-코드바이너리번들-refactorrepository-cleanup)
- [ ] **9. 번들 측정·정리 및 최종 QA**: JS/CSS 청크의 원본·압축 크기와 폰트·선택적 의존성 로딩을 측정하여 개선. 처음 확보한 QA 기준선과 전체 테스트를 다시 수행하고 RPi에서 적용·되돌리기 경로 확인

**진행 규칙:** 1~9단계는 권장 작업 순서이지 하나의 대형 커밋이 아니다. 단계별로 작게 변경하며, 실패한 테스트가 해당 단계의 회귀인지 확인하고 해결한 다음 진행한다. 기능 추가·UI 재설계·API 계약 변경을 리팩터링에 섞지 않는다. 기존 배포 가능한 기준 버전과 롤백 수단을 유지한다.

**통과 대기 3대 검증 게이트**:
- **실제 교시 시각(bell-time) 게이트**: 학교별 교시 시각 검증 완료 후 캘린더 구독에 실제 수업 시작·종료 타임스탬프를 반영(20번).
- **공개 도메인(public-domain) 게이트**: \`opencigan.mcv.kr\` 등 실제 공개 도메인에서 캘린더 구독 및 API의 외부 네트워크 접근 가능성 검증(U02, 39번).
- **실기기(real-device) 게이트**: iOS Safari, Android Chrome, 모바일 캘린더 앱에서의 화면 렌더링 및 동기화 동작 검증(4, 5, 8, 23, 28번).
