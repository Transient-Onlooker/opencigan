## P3 — 알림과 자동화
**2026-11-17 신규 기획 — 체육 알리미·Webhook 발송 시각 설정 (미구현)**

- [ ] **P3 · 당일 체육 수업 오전 알리미**: 사용자가 구독한 학교·학년·반의 **해당 날짜 정규 시간표에 체육 수업이 있으면** 등교 전 지정 시각에 자동 알림. 기본 시각 예시 **07:30 KST**, 사용자별 HH:MM 설정, 요일/채널 선택, 알림 켜기·끄기, 메시지 미리보기와 테스트 발송 지원. 예시: “오늘 3교시 체육이 있어요. 체육복을 챙기세요!” 복수 교시를 합쳐 표시하고 없는 날엔 보내지 않는다. 원본 과목 이름과 별칭을 구별하며 학교별 “체육”, “스포츠” 등 일치 과목을 명시적으로 추가/제외할 수 있게 한다. 구독은 사용자 동의 후 생성하고 우선 기존 Discord·Google Chat Webhook 채널 활용.
- [ ] **P3 · Webhook 예약 발송 및 발송 시간 설정**: 사용자별 **즉시 변경 알림 / 지정 시각 하루 변경 요약 / 등교 전 수업 준비 알리미** 모드를 구분. 발송 예약 시각을 KST HH:MM으로 설정하고 방해 금지 시간, 요일, 변경 유형 조건과 충돌할 경우의 우선순위를 안내한다. 사용자 메시지 템플릿 및 변수·미리보기와 연동하고 **예약 시각과 실제 전송 성공 시각(대기열·재시도 지연 가능)을 구분**한다. 예약 변경·취소·구독 삭제 시 큐 처리 규칙 및 실패 안내를 정한다.
- [ ] **P3 · 사용자 방문 없이 동작하는 알림 스케줄러**: 현재 Webhook은 시간표 변경이 관측되어야 큐에 넣는 구조이므로, **아침에 자동 실행되는 서버 측 예약 작업자**와 학교/반/날짜 기준 캐시 조회가 필요하다. 동일 학급 구독의 중복 원본 요청 억제, 상류 조회 제한·재시도/backoff, 오류·빈 시간표에서 무리한 발송 금지, 데이터 신선도 표시를 설계한다. 구독/학교/반/날짜/알림유형 기반 멱등 키로 중복 발송을 방지하고 재시작·누락·시간표 변경 시 재예약 규칙을 테스트한다. 기존 Webhook 운영 보안/Rate Limit 검증 완료 전에는 활성화하지 않는다.



- [ ] Webhook 구독·삭제·인증·HMAC 서명·재시도·중복 방지 (기본 비활성 API·이력 관측·별도 작업자 로컬 구현 및 모의 테스트. 저장 공간 상한·악용 방지·운영 검증 남음)
- [ ] 기존 [timetable-watcher](https://github.com/Transient-Onlooker/timetable-watcher)의 Google Chat 전송·변경 비교·메시지 생성·중복 알림 방지 로직을 OpenCigan에 재사용
- [ ] 로그인 없이 비밀 관리 링크로 Webhook 구독 생성·수정·삭제하기
- [ ] **Webhook 사용자 지정 메시지 템플릿·미리보기 (아직 미구현)** — 학교·학년·반·날짜·교시·변경 전후 과목·교사·변경 유형 등의 **허용 변수만** 사용하는 구독별 메시지 템플릿 편집, 변경 유형별 문구·Discord Embed·Google Chat 전용 포맷, 실전 전송 없이 샘플 값으로 미리보기 및 테스트 발송, 기본 템플릿으로 되돌리기. 길이·이스케이프·멘션 방지·URL/HTML 삽입 보호와 미정 변수 오류를 검증. 현재 `backend/webhook_store.py`의 메시지는 고정 문구로 생성하고 `frontend/src/webhooks.ts`에서는 필터/방해 금지 시간만 수정 가능하므로 **현재 커스텀 메시지 작성 UI는 없음**. 이 기능과 함께 [P1 개발자용 메뉴 분리](user-experience.md)를 진행.
- [ ] Discord·Google Chat Webhook 알림
- [ ] 학급·변경 수업 필터, 방해 금지 시간, RSS/Atom 피드 (학급별 RSS·Webhook 필터·KST 방해 금지 시간 로컬 구현; 설정 화면·운영 검증 남음)
- [ ] Webhook 설정에서 테스트 알림 보내기와 최근 성공·실패·재전송 이력을 확인하는 기능 (인증된 전송 상태·테스트 큐 API 및 설정 화면 로컬 구현. 운영 검증 남음)
- [ ] 특정 과목·교사·요일·교시·변경 유형을 조합하여 필요한 시간표 변경만 알림받는 기능 (RSS·Webhook 필터 API 로컬 구현. 설정 화면·운영 검증 남음)
- [ ] 같은 날 변경이 여러 번 발생하면 한 번의 요약 알림으로 묶어 보는 기능 (RSS 날짜별 요약 로컬 구현. Webhook 예약·묶음 전송은 미구현)
- [ ] 동일 IP의 과도한 조회, 반복적인 404·429·5xx, 비정상적인 학교 순회 조회를 감지하고 관리자에게 알림

- [ ] **P3 · ‘만들어주세요’ 공감·개발 상태·GitHub 연동 (MVP 후속)**: 승인된 제안에 한하여 공감 투표와 중복 투표 억제, 접수·검토 중·개발 예정·완료 상태를 공개하고 사용자에게 처리 상태를 안내한다. GitHub Issue 생성/연동은 **관리자 승인 후 서버 측에서만** 선택적으로 수행하며 비밀 토큰을 클라이언트에 제공하거나 제안이 GitHub에 자동 공개된다고 가정하지 않는다. 투표·상태 공개는 P2의 안전한 접수·검토가 운영 검증된 후 추가한다.

## 아이디어 보관함 (지금 구현하지 않음)

**개인 시간표·일정 / 시험 오버레이 (기존 구현, UI 제거됨)**

- 공식 시간표와 독립된 수동 수업·시험 일정 기능의 신규 개발을 중단하고 메인·설정의 편집 UI를 제거했다. 기존 브라우저 데이터는 보존하며 설정에서 원본 JSON을 내보낼 수 있다. 앱 내 파일 복원은 지원하지 않는다. [P1 정리 기록](user-experience.md) 참조.

**Jev 기반 급식 취향 하이라이트 (아이디어만 기록)**

- 사용자가 좋아하는 메뉴(예: 돈육불고기)나 선호하는 종류(예: 고기반찬)를 Jev로 분류하여 급식표에서 눈에 띄게 강조하는 기능을 생각해 볼 수 있음.
- **현재 구현하지 말 것.** 개발 체크리스트나 자동 작업 대상으로 취급하지 않고, 추후 필요성·개인화 방식 등을 더 고민한 뒤 결정할 아이디어로만 보관.
