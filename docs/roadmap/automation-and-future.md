## P3 — 알림과 자동화
**2026-11-17 신규 기획 — 체육 알리미·Webhook 발송 시각 설정 (2026-11-24: 격리 구현·자동검증 완료, 운영 미활성)**

- [x] ST-09 핵심 예약 모드·체육/지정 과목·서버 작업자·KST·멱등성·요약 알림 격리 구현 및 자동검증 ([#182](https://github.com/Transient-Onlooker/opencigan/pull/182)). 아래 원래 상세 요구는 운영 적용 및 남은 옵션별 확인 기준으로 보존한다.

- [ ] **P3 · 당일 체육 수업 오전 알리미**: 사용자가 구독한 학교·학년·반의 **해당 날짜 정규 시간표에 체육 수업이 있으면** 등교 전 지정 시각에 자동 알림. 기본 시각 예시 **07:30 KST**, 사용자별 HH:MM 설정, 요일/채널 선택, 알림 켜기·끄기, 메시지 미리보기와 테스트 발송 지원. 예시: “오늘 3교시 체육이 있어요. 체육복을 챙기세요!” 복수 교시를 합쳐 표시하고 없는 날엔 보내지 않는다. 원본 과목 이름과 별칭을 구별하며 학교별 “체육”, “스포츠” 등 일치 과목을 명시적으로 추가/제외할 수 있게 한다. 구독은 사용자 동의 후 생성하고 우선 기존 Discord·Google Chat Webhook 채널 활용. **현황:** ST-09 핵심 구현 및 모의 검증 완료; 운영 활성화·세부 옵션/실제 발송 검증은 별도.
- [ ] **P3 · Webhook 예약 발송 및 발송 시간 설정**: 사용자별 **즉시 변경 알림 / 지정 시각 하루 변경 요약 / 등교 전 수업 준비 알리미** 모드를 구분. 발송 예약 시각을 KST HH:MM으로 설정하고 방해 금지 시간, 요일, 변경 유형 조건과 충돌할 경우의 우선순위를 안내한다. 사용자 메시지 템플릿 및 변수·미리보기와 연동하고 **예약 시각과 실제 전송 성공 시각(대기열·재시도 지연 가능)을 구분**한다. 예약 변경·취소·구독 삭제 시 큐 처리 규칙 및 실패 안내를 정한다. **현황:** ST-09 핵심 구현 및 모의 검증 완료; 운영 활성화·세부 옵션/실제 발송 검증은 별도.
- [ ] **P3 · 사용자 방문 없이 동작하는 알림 스케줄러**: 현재 Webhook은 시간표 변경이 관측되어야 큐에 넣는 구조이므로, **아침에 자동 실행되는 서버 측 예약 작업자**와 학교/반/날짜 기준 캐시 조회가 필요하다. 동일 학급 구독의 중복 원본 요청 억제, 상류 조회 제한·재시도/backoff, 오류·빈 시간표에서 무리한 발송 금지, 데이터 신선도 표시를 설계한다. 구독/학교/반/날짜/알림유형 기반 멱등 키로 중복 발송을 방지하고 재시작·누락·시간표 변경 시 재예약 규칙을 테스트한다. 기존 Webhook 운영 보안/Rate Limit 검증 완료 전에는 활성화하지 않는다. **현황:** ST-09 핵심 구현 및 모의 검증 완료; 운영 활성화·세부 옵션/실제 발송 검증은 별도.
